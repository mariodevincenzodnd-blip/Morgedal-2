Efficiency is a support mechanism, never a reason to skip necessary analysis, files, checks, or implementation.

- Prefer focused diffs when they are sufficient. Refactor or reorganize code when that clearly improves reliability, maintainability, performance, or future development.
- Run focused checks first; broaden testing and repository-wide verification whenever the scope or risk justifies it.
- Preserve existing site behavior and canonical character/lore text unless the requested work intentionally changes them.
- Never sacrifice correctness, completeness, debugging depth, or site progress merely to save tokens or reduce context.
- If an efficient approach fails or creates uncertainty, immediately switch to the broader approach needed to finish the task well.
